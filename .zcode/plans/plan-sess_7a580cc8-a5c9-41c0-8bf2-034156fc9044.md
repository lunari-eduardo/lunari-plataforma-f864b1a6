# PLANO — Corrigir o Editor de Propostas + Evoluir para "Construtor de Página"

## DIAGNÓSTICO (causas raízes verificadas no código)

1. **Duplo clique não edita texto** — `EditableText.tsx:49-63`: o `focus()` roda num `requestAnimationFrame` que pode disparar **antes** de o React aplicar `contentEditable=true` no DOM → sem foco, sem caret, sem `blur` (o commit nunca ocorre). O usuário precisa de um 3º clique — que parece "não funciona". Agravantes: (a) campos vazios renderizam elemento sem conteúdo e **sem CSS de placeholder** (`data-placeholder` existe mas não há regra `:empty::before`) → invisíveis e inclicáveis; (b) o texto permanece como `children` React durante a edição (linha 107) — risco de reconciliação resetar o que foi digitado; (c) a seleção padrão substitui todo o conteúdo ao digitar, em vez de posicionar o caret onde clicou.
2. **Imagens sem duplo clique** — não existe `onDoubleClick` em nenhuma imagem; `VisualRenderer.tsx:386-403` (galeria) e `90-97` (capa) são estáticos. A capa ainda usa **fallback hardcoded do Unsplash** (linha 92) — foto aleatória de terceiros quando não há imagem.
3. **Editorial "quebrado" (retângulos marrom/bege)** — `VisualRenderer.tsx:181-200`: quando não há foto, o slot mostra um gradiente escuro sobreposto com `mix-blend-screen` — sem imagem fica um amontoado de blocos de cor. Sem empty state decente.
4. **Proporções erradas na galeria** — grid com `auto-rows-[150px]/[250px]` fixos + `object-cover`: toda foto é cortada à força; sem controle de proporção; keys instáveis (`img.id || idx`).
5. **"Investimento" duplicado** — o sanitizador do Worker (`sanitize.ts:33-99`) processa blocos individualmente: se a IA retorna 2 `PricingTable`, ambos passam. Precisa mesclar pacotes em um bloco só.
6. **BUG EXTRA GRAVE (descoberto agora)** — `get-public-material/index.ts:96,174` faz `.select('id, nome, whatsapp, avatar_url')` em `profiles`, mas a coluna `whatsapp` **não existe** (o certo é `telefone`/`telefones`) → select falha → CTA de WhatsApp do visualizador público quebrado ("não configurou número").
7. **Wizard pede dados que a conta já tem** — briefing não usa `categorias` (já carregadas no modal), não preenche o nome do fotógrafo (campo correto: `profiles.empresa || profiles.nome`; não existe `nome_estudio`), não oferece os pacotes do ConfigurationContext (o Worker já aceita `packages[]` mas o frontend não envia).
8. **Sem alinhamento de texto** — nenhum bloco tem campo `align`/`ratio`/`aspect` (grep confirma; só classes fixas).
9. **Minor**: fallback de URL do PDF usa `media.lunarihub.com` em vez de `documents.lunarihub.com` (`BibliotecaComercialPage.tsx:197`); label do botão do CTABlock é hardcoded ("Entrar em Contato", linha 350).

## FASE 1 — Editor utilizável novamente (correções críticas)

**1.1 Reescrever `EditableText.tsx` (robusto):**
- Foco/seleção num `useEffect` disparado quando `editing` vira `true` (garantido pós-render), não em rAF.
- Remover o texto dos `children` React enquanto editável (DOM imperativo; efeito só sincroniza fora da edição) — fim do risco de reset do caret.
- Placeholder visível: regra CSS `:empty::before { content: attr(data-placeholder) }` + `min-h`/`min-w` — campos vazios ficam clicáveis.
- Caret no ponto do clique (`caretRangeFromPoint`) em vez de selecionar tudo; toolbar mínima de contexto (negrito/itálico NÃO — texto puro; só um chip "Enter salva · Esc cancela").
- `plaintext-only` quando suportado; hint "duplo clique para editar" no bloco selecionado.

**1.2 Novo componente `EditableImage`** (em `blocks/`): em modo edição envolve cada imagem com overlay hover (ícone câmera + "Trocar imagem") e `onDoubleClick` → file picker → `uploadProposalImage` → commit via `inline.set(path, url)`. Aplicar a: capa (`content.image_url`), fotos A/B do Editorial (`props.photo_a/photo_b.image_ref`), cada foto da galeria (`content.images.N.image_ref`), imagem do pacote (`content.packages.N.image_ref`).

**1.3 Editorial decente sem fotos:** empty state elegante (moldura tracejada neutra com rótulo "Foto A — duplo clique para enviar", só no modo edição; no público, bloco neutro discreto); `mix-blend-screen` só quando as duas fotos existem.

**1.4 Capa sem Unsplash:** placeholder neutro elegante (gradiente suave dos tokens + ícone) substituindo a foto aleatória; duplo clique troca.

**1.5 Botões editáveis:** CTABlock ganha campo `button_label` (painel + inline no botão); CoverBlock garante campos `btn_text`/link no registry V2.

**1.6 Tempo real garantido:** gerar `id` (crypto UUID) para cada imagem no upload/factory; keys estáveis em todos os mapas.

**1.7 Fixes de backend:** `get-public-material` → `select('id, nome, telefone, telefones, avatar_url')` + resolução do número (`telefone || telefones[0]`) no `wa.me`; corrigir fallback do PDF para `documents.lunarihub.com`.

## FASE 2 — Controles de layout por seção

**2.1 Alinhamento de texto** — novo kind de campo `align` no registry (`props.align`: esquerda | centro | direita | justificado); controle segmentado com ícones no painel; renderers aplicam `text-align` nos containers de texto. Blocos: CoverBlock, EditorialBlock, PricingTable, Gallery, TestimonialBlock, CTABlock, text, FooterTerms.

**2.2 Fundo por seção** — estender `props.background` (branco | creme | linho | escuro, usando os tokens `--pa-*`) que o Editorial já tem para Gallery, Testimonial, CTA e PricingTable.

**2.3 Galeria inteligente:**
- `props.layout: 'masonry' | 'grid'` (default masonry). **Masonry**: colunas CSS (`columns-2 @md:columns-4`, `break-inside-avoid`) com proporção **natural** das fotos (`img w-full h-auto`) — nada é cortado, 100% responsivo.
- **Grid**: `aspect-ratio` por imagem (`auto | 1:1 | 4:5 | 4:3 | 16:9`) + spans existentes (normal/alta/larga), sem `auto-rows` fixo.
- Painel: seletor de layout, ratio e ordem por foto (subir/descer). Canvas: tile tracejado "+ Adicionar foto" ao fim da galeria (modo edição) e remover foto pelo hover.
