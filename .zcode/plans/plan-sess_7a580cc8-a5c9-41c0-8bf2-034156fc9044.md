# PLANO — Reconstrução do Construtor de Propostas (módulo Comercial)

## PARTE 1 — DIAGNÓSTICO (revisão completa, código verificado)

### Bugs críticos (quebram funcionalidade hoje)
1. **Edição "às cegas" nos blocos V2** — `PropertiesSidebar.tsx:363-382` (caso `default`) lê `(block.data||{}).title/.content`, mas `handleChange` (linhas 107-121) grava em `block.content` quando o bloco é V2. Para `CoverBlock`, `PricingTable`, `Gallery`, `TestimonialBlock`, `CTABlock`, `FooterTerms`: digitar atualiza a arte, mas o input fica em branco (e o campo "Conteúdo" grava uma string dentro de `content.content`). Só `EditorialBlock` tem formulário dedicado correto.
2. **Race no salvar perde edições** — `useMaterialEditor.ts:203-233`: `saveDraft` captura `state` no clique; edições feitas durante o `await` ficam fora do snapshot, mas `setHasChanges(false)` + `originalState.current = state` (capturado) marcam tudo como salvo — o próximo save retorna cedo (`if (!hasChanges) return`) e as edições nunca são persistidas. Mesmo padrão em `publish` (235-266). Sem trava de duplo clique.
3. **Visualizador público com botões inertes** — `VisualRenderer.tsx:373` envolve TODOS os blocos em `pointer-events-none` (feito para o modo edição, mas o `PublicProposalViewer` reutiliza o componente): CTAs ("Escolher pacote", "Entrar em Contato", links) não clicáveis para o cliente; outline de hover e `cursor-pointer` do editor vazam para o site público.
4. **Capa do template não renderiza o próprio conteúdo** — template seed usa `content: {eyebrow, title_regular, title_italic, photographer_name}`, mas `CoverRenderer` (VisualRenderer.tsx:18-46) lê `title/subtitle/btnText` → capa exibe sempre os fallbacks genéricos; o botão da capa aparece sempre (fallback truthy).
5. **Preview mobile falso** — blocos usam classes de viewport (`md:`, `lg:`) e a moldura mobile (375×812, VisualRenderer.tsx:352) não é container: o layout responde à largura da janela do navegador, não da moldura. Sem container queries no módulo (0 ocorrências).
6. **"Gerar com IA" é mock** — `MOCK_AI_CONTENT` hard-coded (`BibliotecaComercialPage.tsx:44-50`), gera blocos V1 legados que caem no `DefaultRenderer` genérico.
7. **Shares não são imutáveis (promessa falsa)** — o modal promete "a versão atual será travada" (`BibliotecaComercialPage.tsx:718`), mas `saveDraft`/`publish` fazem UPDATE in-place da mesma `material_versions` que o share pinou; `get-public-material` lê `content` ao vivo. Editar após enviar altera retroativamente o que o cliente vê. "Publicar Versão" nunca cria versão 2 (`createMaterial` insere v1 e `publish` só faz update).

### Bugs altos/médios
8. `key={index}` na lista de blocos (`VisualRenderer.tsx:359`) com reordenação dnd-kit.
9. Remover bloco acima do ativo deixa `activeIndex` apontando para outro bloco (`EditorPropostaPage.tsx:224-229`).
10. Sem autosave, sem `beforeunload`, sem undo/redo — "Voltar" navega direto e perde tudo silenciosamente.
11. Modal "Personalizar Link Público" inacessível (`setIsSlugModalOpen(true)` nunca chamado; `slugInput` nunca inicializado) — `EditorPropostaPage.tsx:325-364`.
12. "Duplicar Proposta" desabilitado no editor (`EditorPropostaPage.tsx:169-171`).
13. Excluir proposta sem confirmação; `deleteMaterial` deleta shares manualmente para contornar `ON DELETE RESTRICT` (destrói analytics silenciosamente).
14. Editor sem responsividade: colunas fixas `w-[280px]`/`w-[340px]` sem breakpoints; toggle central `absolute` sem pai `relative`.
15. `setState` durante render no `PublicProposalViewer.tsx:136-139` (flash de tela branca).
16. Token de share gerado com `Math.random()` (não criptográfico); `view_end` duplicado (unmount + beforeunload + visibilitychange); heartbeat tipado `as any`.
17. Storage inconsistente: PDF criado vai ao bucket Supabase `proposals_pdfs`, substituição no editor vai a R2 (`proposals-pdf`), imagens a R2 (`proposals`) — 3 caminhos.
18. `alert()` para erro de upload (PropertiesSidebar.tsx:133,399) em vez de toast; `hasImageField` (linha 386) exclui `CoverBlock`/`Gallery` (sem upload de imagem nesses blocos).
19. Defaults V1 incoerentes com renderers (ex.: default `package.name` vs renderer lê `data.title`); `getBlockName` não conhece tipos V2 ("Seção").
20. Performance: `JSON.stringify` duplo por teclada (`useMaterialEditor.ts:110-113`) + `VisualRenderer` sem `React.memo` → re-render da arte inteira a cada tecla.

### Segurança (backend)
21. **RLS permissiva cross-tenant**: policies anônimas `USING (is_active = true)` em `material_shares` (expõe `note` interna, tokens, lead_id de TODOS os fotógrafos), `material_share_links` e `material_share_link_slugs` (`USING (true)`) — qualquer anônimo lista tudo com `select *`.
22. View `share_analytics_summary` sem `security_invoker` (bypassa RLS; não usada pelo frontend — superfície de ataque sem função).
23. `track-share-event`: service role, sem rate limit, sessão recuperada sem validar que pertence ao share (spam de métricas); salt default fraco.
24. `validate-proposal`/`assemble-context`: órfãs (nenhum caller) e consultam `component_registry`/`ai_generation_logs` sem prefixo de schema (tabelas vivem em `system.`/`quoting.`) — provável relation-not-found em runtime.

### Dead code / dívida
25. `ConstrutorComercialPage.tsx` inteiro não roteado (e com bug: abre `/p/${material.id}` — id no lugar do token).
26. Duas gerações de blocos (V1: cover/about/package/faq/cta/text; V2: CoverBlock/EditorialBlock/PricingTable/Gallery/TestimonialBlock/CTABlock/FooterTerms) sem registry, sem schema, com variantes/design_tokens/editable_fields do template **mortos** (nenhum renderer lê `variant`; `design_tokens` nunca aplicado — cores hard-coded).
27. `proposal_templates` só tem 1 seed ("Editorial Sofisticado") e não é editável por UI (nenhum INSERT/UPDATE no src).
28. EstrategiaComercialPage: 5 abas placeholder; schemas `commercial`/`quoting`/`system` (Context Engine) não conectados ao frontend; imports não usados; `(supabase as any)` em todo o módulo apesar dos tipos existirem; `tsconfig` com `strict:false` mascarando tudo.

## PARTE 2 — ARQUITETURA ALVO

Decisões de produto confirmadas: **módulo permanece admin-only**; IA com **geração completa + ajuda por campo + assistente de layout/design pós-criação**.

**1. Registry declarativo de blocos (fonte única de verdade)** — novo `src/pages/comercial/blocks/`:
- `registry.ts`: para cada tipo V2 declara `{ type, nome, ícone, categoria, variantes[], factory() (conteúdo default), fields[] (schema de campos: key, label, tipo input, placeholder, lista/objeto aninhado), imageSlots[], renderer }`.
- O registry passa a alimentar: menu "Adicionar Seção" (EditorSidebar), formulário do painel direito (gerado a partir de `fields` — elimina o switch manual e o bug #1 por construção), mapa de edição inline (campo→elemento), validação de payload da IA e o assistente de layout.
- Renderers migrados para `blocks/renderers/` consumindo `variant` e `design_tokens` (cores/tipografia via CSS variables no root da arte).

**2. Modelo de documento unificado (só V2)** — `BlockData` vira `{ id, type, variant?, content, props? }`; `global_settings` sai do array e vai para campo próprio do estado (fim do bloco sintético espiado no save/load). Normalização V1→V2 na carga (`normalizeBlocks`) + backfill opcional one-time.

**3. Modos de renderização explícitos** — `VisualRenderer` recebe `mode: 'edit' | 'preview' | 'public'`: overlay/outline/pointer-events só em `edit`; em `public` os CTAs ficam funcionais (WhatsApp do perfil, âncoras) e sem estética de editor (mata bug #3).

**4. Responsividade real com container queries** — arte envolta em `@container`; renderers reescritos de `md:` para `@md:` (Tailwind 3.4 tem container queries nativo — confirmar versão no package.json; se inferior, plugin `@tailwindcss/container-queries`). A moldura mobile passa a exercitar o layout real; o visualizador público responde ao container (mobile de verdade).

**5. Estado do editor com reducer + histórico** — `useProposalEditor` (evolução do `useMaterialEditor`): reducer imutável, pilha undo/redo (Ctrl+Z/Y), autosave debounced (2s) + flush em `beforeunload`/navegação (bloqueio com dialog "alterações não salvas"), diff por referência estrutural (fim do `JSON.stringify` por teclada), snapshot funcional no save (mata a race #2), `React.memo` nos renderers.

**6. Edição inline no desktop** — em `mode:'edit'` com viewport ≥ lg: duplo clique (ou clique em texto) ativa `contentEditable` no elemento (componente `EditableText` com commit no blur/Enter, sem re-render durante a digitação — caret estável); clique em imagem seleciona o bloco e abre o upload no painel; clique simples seleciona o bloco; Esc/desenho clicável fora sai da edição. O painel lateral continua existindo e sincronizado (mesma fonte de estado).

**7. Versionamento e imutabilidade de shares** — `publish` cria NOVA linha em `material_versions` (version_number+1; trigger existente `sync_active_version_on_publish` aponta `active_version_id`); `saveDraft` atualiza apenas a versão-rascunho mais recente (cria rascunho novo se a última estiver publicada). Shares pinados em `version_id` ficam imutáveis de fato (a promessa da UI passa a ser verdade — `get-public-material` já lê a versão pinada, não precisa mudar).

**8. IA real reutilizando a infra existente** — novo adapter no padrão de `assistant-chat` (provedores multi-gateway, chaves em vault; NÃO novo provedor):
- **Geração completa**: wizard "Gerar com IA" coleta briefing (tipo de ensaio, cliente, tom, pacotes do ConfigurationContext, faixa de preço) → edge function `proposal-generate` retorna `blocks[]` V2 **validados contra o registry** (campos desconhecidos descartados; log em `quoting.ai_generation_logs` com prefixo de schema correto). Resultado 100% editável (é um material comum).
- **Ajuda por campo**: botões "Melhorar / Reescrevar / Encurtar / Traduzir tom" em cada campo de texto (painel + toolbar da edição inline) → edge `proposal-ai-field` com contexto (bloco, campo, briefing do material).
- **Assistente de layout/design pós-criação** (painel "Lu" no editor): sugestões de estrutura (adicionar/remover/reordenar seções a partir do registry), aplicar variante de bloco, ajustar paleta/tipografia (`design_tokens`) — operações restritas a uma allowlist (mesma filosofia do automation-scheduler), com preview e "aplicar" explícito.

**9. Modelo padrão editável** — `proposal_templates` ganha CRUD no admin (o editor ganha "modo template": editar template usa o mesmo construtor; "Salvar como modelo" a partir de qualquer proposta; 3-4 seeds novos: Editorial, Clássico, Minimalista, Moderno). Coluna `thumbnail_url` para a galeria do wizard.

**10. Editor responsivo** — shell com breakpoints: ≥lg = 3 colunas; md = canvas + painéis em drawers (esquerda: estrutura; direita: propriedades); mobile = prioridade canvas com drawer único. Zoom do canvas (fit/75/100%) — hoje inexistente.

## PARTE 3 — FASES DE EXECUÇÃO

### Fase 1 — Correções críticas (sem mudar arquitetura)
- Corrigir race do save (snapshot funcional + guarda `saveStatus==='saving'`) e adicionar `beforeunload`.
- Corrigir caso `default` do PropertiesSidebar (ler de `block.content` quando V2) como stop-gap até o registry.
- `VisualRenderer`: prop `mode` para separar edição de público (remove pointer-events-none/outline no público).
- Corrigir remoção de bloco (ajustar `activeIndex` sempre), `key={index}` → `key={block.id}`, `setState`-durante-render do viewer público, toggle absolute → pai `relative`.
- Mapear campos do CoverBlock no renderer (title_regular/title_italic/eyebrow) + defaults V1 coerentes.
- Token de share com `crypto.getRandomValues`; confirmação antes de excluir; habilitar "Duplicar" no editor; wire do modal de slug (abrir + inicializar valor).
- RLS: revogar SELECT anônimo de `material_shares`/`material_share_links`/`material_share_link_slugs` (o público já é servido por `get-public-material` com service role — migration nova); dropar `share_analytics_summary` (não usada).
- Remover `ConstrutorComercialPage.tsx` e imports mortos.

### Fase 2 — Fundação do registry + documento V2 único
- Criar `blocks/registry.ts` + `blocks/renderers/` (mover os 9 renderers); formulário do painel direito gerado do schema; menu "Adicionar Seção" do registry; `normalizeBlocks` V1→V2 na carga; `global_settings` fora do array.
- Tipagem: interfaces tipadas por bloco, fim do `(supabase as any)` (tipos já existem em `src/integrations/supabase/types.ts`).

### Fase 3 — Responsividade + design tokens
- Container queries na arte (plugin se necessário); reescrita dos breakpoints dos renderers; consumo de `design_tokens`/`variant`.
- Shell do editor responsivo (3 colunas → drawers) + zoom.

### Fase 4 — Experiência de edição
- Reducer + undo/redo + autosave debounced + bloqueio de navegação.
- Edição inline `EditableText` no desktop (texts) + seleção de imagem na arte.
- Uploads unificados em R2 (contexto `proposals` / `proposals-pdf`), toast em vez de alert, `onError` de imagem com fallback.

### Fase 5 — Versionamento real
- `publish` cria nova versão; rascunho separado da publicada; UI de histórico de versões (listar, restaurar, duplicar a partir de). Shares imutáveis.

### Fase 6 — IA
- Edges `proposal-generate` e `proposal-ai-field` (reutilizar `_shared` de assistant-chat; log em `quoting.ai_generation_logs` com schema correto); wizard de briefing real substituindo o MOCK; botões por campo; assistente de layout/design com allowlist + preview/aplicar; validar saída contra registry.
- Corrigir ou remover `validate-proposal`/`assemble-context` (prefixo de schema) conforme uso pela IA.

### Fase 7 — Modelos editáveis
- CRUD de `proposal_templates` (modo template no editor, "Salvar como modelo", thumbs) + novos seeds.

**Ordem sugerida: 1 → 2 → 3 → 4 → 5 → 6 → 7** (cada fase entrega valor isolado; 6/7 podem ser paralelizadas após a 4).
